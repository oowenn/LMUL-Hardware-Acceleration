How It Works

Multiplication → Addition

Instead of O(n²) mantissa multiplication, L-Mul exploits logarithmic representation for O(n) addition.

The Key Insight

1

Extract BF16 Fields

Split 16-bit input into sign (1), exponent (8), mantissa (7 bits).

2

Add Instead of Multiply

Treat exponent+mantissa as single field. Add with bias correction (0x4080).

3

Handle Overflow

Check carry bits to detect overflow/underflow and saturate.

4

Apply Correction

Add small factor (result/32 + result/64) to improve accuracy.

lmul_nn_funcs.py
def lmul_bits(a, b):
    # Convert to int32 for bit manipulation
    a_bits = a.view(torch.int32)
    b_bits = b.view(torch.int32)
    
    # Extract BF16 from upper 16 bits
    a_bf16 = (a_bits >> 16) & 0xFFFF
    b_bf16 = (b_bits >> 16) & 0xFFFF
    
    # Extract sign and field
    a_sign = (a_bf16 >> 15) & 0x1
    b_sign = (b_bf16 >> 15) & 0x1
    a_field = a_bf16 & 0x7FFF
    b_field = b_bf16 & 0x7FFF
    
    # L-Mul: Add with bias correction
    sum_full = a_field + b_field + 0x4080
    carry = (sum_full >> 15) & 0x3
    
    # Handle overflow
    field_sel = torch.where(carry == 1, sum_full & 0x7FFF, 0)
    field_sel = torch.where(carry >= 2, 0x7FFF, field_sel)
    
    # Pack result
    s_result = a_sign ^ b_sign
    result = ((s_result << 15) | field_sel) << 16
    result = result.view(torch.float32)
    
    return result + (result / 32) + (result / 64)

Key Insights

Hardware design implications

LSTM: State updates benefit from L-Mul. Prioritize state computation paths.
CNN: FC layers more tolerant than conv layers. Focus L-Mul on classification heads.
Transformer: More L-Mul = lower perplexity! MLP + LM Head performs best.
Overall: L-Mul may act as implicit regularization. Dense/linear layers are excellent candidates.
