Making neural networks faster by replacing multiplication with addition

L-Mul is an approximate multiplication algorithm that uses ⅓ of the silicon area while maintaining 99%+ accuracy. We're building the hardware and software to prove it works.

The Problem

Why this matters

Neural networks are everywhere — phones, cars, data centers. But they're expensive to run. The bottleneck? Multiplication. Billions of floating-point multiplies burning through power and silicon.

⚡

Energy consumption

A single GPT-3 query uses enough energy to charge your phone. Data centers running AI models consume gigawatts. Multiplication is a big part of that cost.

📱

Edge deployment

Running ML on phones, watches, and IoT devices means working with tiny power budgets. Traditional floating-point hardware is overkill.

💰

Hardware cost

Multiplier circuits take up significant silicon area. If we could shrink them, we could fit more compute in the same chip — or make cheaper chips.

The Algorithm

How L-Mul works

The key insight: floating-point numbers already encode magnitude logarithmically (in the exponent). Since log(a×b) = log(a) + log(b), we can approximate multiplication with addition.

O(m²)

IEEE 754 Standard

result = sign ⊕ (exp_a + exp_b − 127) + (mantissa_a × mantissa_b)

Standard floating-point multiplication requires a full mantissa multiply — that's a 7×7 bit multiplication for BFloat16, needing dedicated hardware.

O(m)

L-Mul Approximation

result = sign ⊕ (field_a + field_b + 0x4080)

L-Mul treats exponent+mantissa as one field and just adds them. No multiplier hardware needed — just an adder and some control logic.

// BFloat16 L-Mul in 4 steps // 1. Extract fields sign_a = a[15] // sign bit field_a = a[14:0] // exponent + mantissa as one 15-bit integer // 2. Add with bias correction sum = field_a + field_b + 0x4080 // offset compensates for doubled exponent bias // 3. Handle overflow/underflow if (sum[16:15] == 0b00) → underflow → return 0 if (sum[16:15] == 0b01) → normal → result_field = sum[14:0] if (sum[16:15] >= 0b10) → overflow → result_field = 0x7FFF // 4. Pack result result = (sign_a ⊕ sign_b) << 15 | result_field
Results

Does it actually work?

We tested L-Mul across multiple neural network architectures. The accuracy loss is minimal — neural networks are surprisingly tolerant of approximate arithmetic.
